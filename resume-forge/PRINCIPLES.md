# 强简历写法原则（从一份顶尖技术简历蒸馏）

这份文档提炼"一份写得好的技术/AI 简历"在**语言、结构、信息密度**上的可复用规律。
润色或新写简历时逐条对照；这些是"为什么读起来强"的底层原因，不是模板套话。

---

## 一、结构：每个项目都走 背景 → 目标 → 我的职责 → 指标/效果

强简历的每段经历不是"我做了 X"，而是一个可验证的闭环：

- **背景**：这个项目要解决什么真实问题、痛点在哪（一两句，点出"为什么值得做"）。
- **目标**：明确、可衡量（"提升难题通过率，降低重复推理成本"）。
- **我的职责**：**用第一人称 + owner 身份**说清自己端到端做了什么，带技术深度。
- **指标与效果**：**量化**结果，最好带"前→后"对比。

> 反例（弱）：负责了一个 Agent 项目，做了数据分析功能。
> 正例（强）：**项目 owner，从 0 到 1** 设计并落地电商产运 Agent；上线后**月均调用 600+ 次**，单次分析报告**从人工 1–2 小时缩短至 5–15 分钟**。

---

## 二、量化一切（数字是简历的硬通货）

原简历几乎每条都有数字，且分两类：

- **绝对量**：stars 76k、月活 500+、付费用户 200+、11 层流水线、10+ scaffold。
- **相对提升（前后对比）**：通过率 +25%、成本 −30%、转化率 38%、耗时从 2–4h → 15–30min。

原则：
- 能量化就量化；没有精确值就给**区间或量级**（600+、约 40%、10+ 种）。
- 相对提升永远配"相对什么基线"（"较全量重跑提升 25%"）。
- 不编造数字。真没有就写机制性收益（"新增能力只改对应层，推理代码零改动"）。

---

## 三、owner 身份 + 动作导向动词

- 反复用 **"项目 owner，完全负责从 0 到 1 设计并落地"** 建立"我主导、不是打杂"的印象。
- 句子以强动词开头：**主导 / 负责 / 设计 / 落地 / 复现 / 提升 / 降低 / 抽象 / 统一**。
- 避免"参与了""协助""帮忙做了些"这类稀释所有权的措辞。

---

## 四、技术深度：给出真实机制，而不是名词堆砌

弱简历："基于大模型做了一个 Agent 系统。"
强简历给**可验证的架构与机制**：

- 具体流程链路：`Coordinator（意图识别）→ Planner → Research Team → Reporter`。
- 命名有序结构：`11 层有序流水线（ThreadData → Uploads → Sandbox → … → Clarification）`。
- 关键策略讲清"怎么做的"：`三阶段交接：规则压缩历史为 ~12k → LLM 反出 RFC → 裁剪对话作为下一模型输入`。

判据：一个懂行的人读完，能大致画出你的系统图 —— 这才叫技术深度。

---

## 五、命名概念（把思考显性化）

原简历自造/沿用了一批**记得住的概念名**，signal 深度思考：

- Context Engineering 拆成 **Write / Select / Compress / Isolate** 四动作。
- **Evidence-to-Action Gap**（能定位证据但无法转化为行动）。
- **Failure Onset**（首次出现错误决策的步骤）。
- **Middleware Chain**、**Skill System**、**Test-in-Loop**。

原则：当你对某个问题有独到抽象时，**给它起个名字**并一句话定义。比十句形容词都有力。

---

## 六、对比框架：展示迭代与判断力

- "**相比 1.0** 五节点固定流水线，**2.0 改为**单一 Lead Agent 统一决策" —— 展示你不是一次做对，而是**发现问题→重构→更优**。
- "1.0 逻辑散落各处，改一处要变动多处；2.0 抽成 11 层，只改对应层" —— 暴露旧方案缺陷 + 你的解法，体现工程判断。

---

## 七、语言风格：中英精准混排、简洁、不注水

- 技术术语用**英文原词**内联（scaffold、checkpoint、patch、SFT/RL、Rubric），显专业与信息密度。
- 中文做骨架和逻辑连接词，英文做精确术语 —— 读起来快、不外行。
- **删掉一切形容词水分**："非常强大的""业界领先的"→ 换成数字或机制。
- 用 `等宽字体` 标出代码级实体（`system_prompt`、`memory.json`、`read_file`、CLI 命令），一眼区分"这是系统里真实存在的东西"。

---

## 八、信息密度与可扫描性（排版即内容）

- **层次化项目符号**：项目 → 背景/职责 → 子机制 → 细节，最多 3–4 级，缩进清晰。
- **视觉锚点**：蓝色小节标题 + 分割线、公司 logo 色块、加粗关键结论、内联代码框 —— HR 6 秒扫一遍能抓到重点。
- **加粗只加"结论与数字"**，不通篇加粗（加粗过多 = 没有重点）。

---

## 九、成就组织：密而不乱

原简历末尾把开源/竞赛/合作压缩成高密度但分类清晰的几条：

- **开源**（Apache Committer + 具体项目 + 竞赛奖项）
- **黑客松**（作品 + 奖项）
- **行业合作**（VC 被投公司 / 大模型厂商，产出物）

原则：成就多时**按类型聚类**，每类一行，最有分量的（"18 岁全球最年轻 Apache Committer"）放前面并加粗。

---

## 十、润色时的"只改措辞不改事实"红线

- 只优化**表达**（动词、结构、量化措辞、术语精准度），**绝不编造或夸大**未发生的经历、数字、职称。
- 数字缺失→标注让作者补，不要凭空填。
- 保留作者真实的技术判断与命名，不用通用套话替换掉有个性的表达。
